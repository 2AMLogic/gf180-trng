# `sim/tb/conditioner-crc32/` — conditioner demonstration (behavioral)

Simulated raw bitstream in, conditioned bitstream out. This is the
demonstration run [`DR-0008`](../../../spec/decision-records/DR-0008-crc32-lfsr-non-vetted-conditioner.md)
cites, produced at the level fixed by
[`DR-0009`](../../../spec/decision-records/DR-0009-behavioral-vs-transistor-verification-split.md).

**This testbench has no `tb.json` and is not an ngspice testbench.** Per
DR-0009 rule 7, a behavioral testbench is deliberately invisible to
`sim/run_corners.py` (which only discovers directories containing a
`tb.json`), so it cannot be swept across a PVT grid it has no meaning on.
It is run directly:

```sh
python3 sim/tb/conditioner-crc32/run_demo.py --no-write   # print only
python3 sim/tb/conditioner-crc32/run_demo.py              # mint records
python3 sim/tb/conditioner-crc32/run_demo.py --scenario h050
```

## Files

| File | What it is |
|---|---|
| `run_demo.py` | The testbench. Runs the fixed scenario set and writes one append-only evidence record per scenario. |
| `source_model.py` | The declared synthetic raw source: an IID biased coin with a chosen per-sample min-entropy, generated by SHA-256 counter mode so a stream is bit-identical on any platform. |
| `sp800_90b.py` | SP 800-90B conditioning-component output-entropy arithmetic, so DR-0008's numbers are computed rather than asserted. **Read its provenance warning before quoting anything from it.** |
| `tb_rtl_equivalence.v` | Icarus Verilog testbench driving `design/conditioner/crc32_conditioner.v` from a per-cycle stimulus file, for the RTL/model equivalence check in `sim/tests/test_conditioner.py`. |

## Scenarios

| Scenario | Source | Why it is in the set |
|---|---|---|
| `h050` | IID, H = 0.5 bit/sample | the DR-0002 / DR-0007 design target |
| `h0107` | IID, H = 0.106456 | the K = 8 break-even: below this the conditioner, not the non-vetted cap, limits output entropy |
| `h003` | IID, H = 0.03 | DR-0002's hard floor — included to show what the conditioner does **not** fix |
| `stuck0` | stuck at 0, H = 0 | a dead source; the output words are all zero |
| `gate-flush` | IID H = 0.5 + scripted flushes | the DR-0001 / DR-0002 flush rule: no pre-flush bit influences any later word |

## What these runs do and do not show

They show the **block**: the compression ratio is exactly K, one word
depends on exactly 256 raw samples, the flush discards the partial block,
and the RTL and the model agree.

They show **nothing about the entropy source**. The input is a declared
synthetic model chosen because its min-entropy is known exactly, not a
jitter-sampled ring oscillator (which is neither IID nor stationary across
corners). #9 owes the real raw bitstream, #12/#13 owe its min-entropy.

They also have **no P/V/T corner**, so they may not be cited for rate,
power, or timing (DR-0009 rule 3).

The `h003` scenario is the one worth reading twice: a raw stream with a
measured min-entropy of ~0.03 bit/sample produces a conditioned stream with
`P(1)` within a fraction of a percent of 0.5. A linear conditioner spreads
a low-entropy input across the whole 2³² output space, so **passing a bias
test on the conditioned stream says nothing about the entropy behind it.**
